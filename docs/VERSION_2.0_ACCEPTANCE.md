## 1–13 项查收表

### 1. 恢复摘要优化

- 调整：右侧首先显示可读的恢复范围、映射、完整性、目标系统、处理方式和提醒；原始 JSON 收入“技术详情”折叠区。
- 查收：生成恢复计划后，不展开技术详情也能判断“恢复什么、恢复到哪里、有什么风险”。
- 通过标准：技术详情默认关闭；可读摘要与 JSON 指向同一计划；恢复完成/失败/回退状态明确。

### 2. 恢复选择细化

- 调整：对话记录和 Skills 会展开到每一条实际数据；既支持整类全选/清空，也支持单条勾选；高风险项选择时二次确认。
- 查收：先清空，只勾选某一条具体对话，再生成计划。
- 通过标准：只产生该对话的一条目标映射；同目录里的其他对话不删除、不覆盖；全选数量等于可恢复项数量。

### 3. 备份选择联动

- 调整：上方主方案与下方精细选择代表同一备份结果；上方已全量包含时，下方显示“全量已包含”并锁定重复选择；保留“一键全选”和“恢复推荐”。
- 查收：勾选/取消上方“对话记录”和“Skills”，观察下方项目、对话、Skills 状态。
- 通过标准：上下状态同步；底部只有一个主“创建备份”入口；广泛分类和精细单项进入同一个恢复点。

### 4. API 项目优化

- 调整：API 名称沿用扫描到的原始名称；悬停显示 Provider、用途、使用项目和恢复后重配说明；不显示或保存 API Key。
- 查收：展开“API 接入记录”，搜索并悬停任一项目。
- 通过标准：原名不被改写；说明可读；密钥内容不可见且不进入恢复点。

### 5. Skills 搜索与说明

- 调整：Skills、项目、对话、API、插件等大量项目支持搜索；Skill 优先显示用户配置的 `display_name`/标题/一级标题，保留内部 manifest 名称作为辅助信息；悬停显示简洁能力说明。
- 查收：使用关键词搜索 Skill，再清空搜索。
- 通过标准：搜索结果正确收窄；清空后恢复；长说明不破坏布局。

### 6. 登录凭据安全说明

- 调整：`auth.json`、登录 Token、API Key 和账号会话永久排除；关闭“排除插件与本地工具”也不会解锁登录凭据。
- 查收：在设置中关闭高风险排除开关，检查登录凭据卡片。
- 通过标准：插件/本地工具可按策略开放；登录凭据始终禁用、未勾选，并显示“永久排除”。

### 7. 恢复跨系统提示

- 调整：Windows、macOS、Linux 显示目标路径示例、路径格式、工具架构、执行权限和重新授权说明；跨系统计划显示适配任务。
- 查收：分别选择 Windows、macOS、Linux。
- 通过标准：每个系统提示不同；macOS 明确 Apple Silicon/执行权限；跨系统高风险恢复需要确认。

### 8. 备份与恢复进度

- 调整：备份与恢复在后台线程执行，按真实文件字节、文件数、复制和 SHA-256 校验阶段流式返回百分比、当前任务、已处理量和预计剩余时间。
- 查收：创建一份包含多个分类的备份，再执行恢复。
- 通过标准：操作期间持续出现多个中间百分比，单调增加并以 100% 结束；显示“已处理 / 总量”；文案随扫描、写入、校验、回滚保护、复核变化；失败时显示自动回退状态。

### 9. 全局按钮验收

- 调整：所有按钮使用有色玻璃底；扫描、文件夹、备份、恢复、风险、保存、调整和重置具有不同语义色；悬停时增加明显上浮、亮度/饱和度、双层阴影、宽幅玻璃扫光和主色边缘流光，按压时下沉。
- 查收：依次检查五页的普通、悬停、按压、禁用按钮和删除按钮。
- 通过标准：没有透明无色按钮；没有点状高光/星光；动效沿按钮主色移动；高风险操作为红/灰语义。

### 10. 品牌 CL 图标动效

- 调整：磨砂玻璃背景循环流动，CL 镜面字母固定居中；系统“减弱动态效果”下切换静态图。
- 查收：观察侧栏图标 5–10 秒并切换页面。
- 通过标准：背景确实变化；CL 不漂移、不旋转；无闪烁；减弱动效模式不播放循环动画。

### 11. 最终 UI 精修

- 调整：统一五页色块、卡片层级、玻璃按钮、恢复工作区和窄桌面宽度。
- 查收：在 1440×1000、1280×720、1365×1170、1276×1136 查看五页。
- 通过标准：无横向溢出、控件裁切、文字重叠或按钮漏色；页面主色调仍与原版一致。

### 12. macOS M 系列版本

- 调整：DMG + ZIP 均固定 `arm64`；最低 macOS 12；包含 icns、hardened runtime、entitlements、架构/DMG/ZIP/启动验证和 Apple Silicon GitHub runner。
- 已自动验证（Windows）：生成真实未签名 `.app.zip`；主程序 Mach-O 为 `arm64`；Bundle ID、最低系统版本、自定义 icns、`app.asar`、ZIP 结构和 Unix 执行权限通过。
- 查收：先在 M1/M2/M3/M4 Mac 解压 `Codex-Link-2.0.0-mac-arm64-unsigned-app.zip` 并启动；再解压源码包运行 `npm run package:mac:arm64`，或手动运行 GitHub Actions 工作流生成 DMG。
- 通过标准：生成 `Codex-Link-2.0.0-mac-arm64.dmg` 和 ZIP；`lipo -archs` 为 `arm64`；DMG 可挂载；ZIP 可解压；从最终 ZIP 解压的应用启动 8 秒不退出；`qa/reports/macos-arm64-release-latest.json` 为 `passed`。发布签名模式还必须证明 hardened runtime、entitlements、签名和公证票据均通过。
- 当前限制：Windows 主机不能运行、签名或公证 Mac 应用，也不能恢复依赖 `codesign` 的 ASAR 完整性强制、创建/挂载最终 DMG；需要 Apple Silicon runner 完成剩余产物证据。

### 13. Windows 安装包与人工验收

- 调整：版本升级到 2.0.0，生成可选安装目录的 x64 NSIS 安装包。
- 已自动验证：静默安装到自定义目录成功、安装后启动至少 6 秒并创建真实恢复点、静默卸载成功、恢复点保留、打包版真实备份/恢复/回滚通过、设置持久化通过。
- 查收：双击安装包，选择测试目录安装；完成 1–11 项；卸载后确认真实备份文件夹仍保留。
- 通过标准：安装/启动/卸载无报错；备份数据不随卸载删除；自动 P0 全部通过；人工评分完成且总分至少 90。

## 人工评分操作

1. 由独立验收人初始化文件：

   ```powershell
   npm run manual:init -- --reviewer QA-01
   ```

2. 在 `qa/manual-review.json` 中填写至少 5 位首次使用者（其中至少 3 位目标用户）、证据附件、实际观察和七类分数，并将 `confirmedIndependent` 设为 `true`。
3. 先校验人工材料：

   ```powershell
   npm run manual:validate
   ```

4. 执行正式发布门禁：

   ```powershell
   node scripts/codex-link-self-check.js --profile release --manual qa/manual-review.json
   ```

5. 正式通过条件：人工文件结构与证据通过、报告为 `PASS`、所有 P0 通过、人工项目全部填写、总分不少于 90。
